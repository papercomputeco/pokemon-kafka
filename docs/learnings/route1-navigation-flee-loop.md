winner:        Shipped on main (2026-08-16, `fix/battle-wedge-and-flee-cap`) as two agent.py changes, no genome change: (1) a battle-wedge watchdog in PokemonAgent.run — when (battle_type, player_hp, enemy_hp, move_pp) is identical for BATTLE_WEDGE_TURNS=2 consecutive turns, `_recover_battle_wedge()` presses B x8 and idles 120 frames (B only — no A-mash; max BATTLE_WEDGE_MAX_ATTEMPTS=4 per signature, reset at battle end; count reported as `battle_wedge_recoveries` in fitness); (2) the stall-run cap in BattleStrategy.choose_action — after WILD_STALL_RUN_CAP=3 stall-guard run attempts (not 10), fall back to fight with the best-scored move via _pick_move (not a fixed move_index 0) and re-arm the guard, so a futile battle alternates 10 fights / 3 runs.
why it worked:  The loop is not a wrong branch, it is a wedged screen. Savestates dumped from the evals/cases/low-hp-wild-battle lane show it: the battle opens on the "Go! CHARMANDER!" text, the run branch's d-pad presses are eaten by it, and its A-mash lands on the battle menu whose remembered cursor is on PKMN — from then on the agent is inside the party screen ("Choose a POKeMON" / SWITCH-STATS-CANCEL / "is already out!") and every fight/run selection just cycles that submenu: no PP is spent, no HP moves, 3 low-HP runs, 10 fight turns landing nothing, run forever (main: 600 turns, 3 encounters). The stall-run cap ALONE does not break it (10 fights / 3 runs / 10 fights ..., still 600 turns on Route 2), because the wedged screen accepts neither. B x8 does: it closes the nested submenu and is a no-op on the top menu, after which the normal selection (which normalises the cursor to FIGHT) lands — verified from five wedged savestates; Qwen 3.8's original recipe (B x8, A x3, wait 240) unwedged the relay lane but the A-mash re-enters the PKMN submenu when fired before a fight turn (4 recoveries, still stuck), so the shipped recovery is B only. Result: low-hp-wild-battle PASS 356 turns / Forest / 4 won (was FAIL 600 / Route 2 / 3). The cap never fires with the watchdog in place, so it is kept as the guard against the provably infinite `run` branch, not as the fix for the observed loop. The health half was a second, unwedged mechanism (fixed on `fix/battle-health-menu-timing`, same day): the fight branch's blind `up, left, A, down x idx, A, A, A x8` assumed the turn opens on the battle menu with the move-list cursor on slot 0, but the previous turn's A-mash left it anywhere between the enemy's text and an open move list, and Gen 1 remembers both cursors (0xCC2D / 0xCC2E) — instrumented on Route 2, the normalising `up` wrapped Scratch → Growl and every later FIGHT reopened on Growl while Pidgey chipped 17 → 1 HP; a low-HP `run` had its d-pad eaten by text and its A landed on FIGHT. Now every action syncs to the drawn battle menu first (B until the FIGHT tiles are in wTileMap), walks the cursor it reads from RAM one verified step at a time, and takes the PP/HP delta as proof the move landed (wBattleMonPP is d02d..d030; the profile read it a byte early): route1-to-forest lands 25/25 fight turns (was 19/36) and low-hp-wild-battle needs no wedge recovery at all (PASS 194 turns, 0 WEDGE). It still arrives at the Forest gate with 1-5 HP: with every turn landing, that is the fight-first policy taking a Gust per turn down to hp_run_threshold=0.2, a run/heal decision rather than a menu problem (see evals/results/2026-08-16.md, notes). RESOLVED for this obstacle (2026-08-16): the loop is gone and the eval was re-scoped to say so — `evals/cases/route1-flee-loop.json` is now `evals/cases/route1-to-forest.json`, asserting only what the case detects (reach map 51 from route1.state in <=2000 turns): PASS 934 turns / 51 / 9-9 battles, byte-identical under PYTHONHASHSEED 0/1/7. The old `min_lead_hp: 5` criterion was dropped rather than lowered: it described a downstream entry condition, not this lane, and that condition no longer binds (forest-crossing-1hp XPASSes — a 1-HP forest entry now reaches Pewter at 22 HP); it was also frame-sensitive (1 HP vs 5 HP on a 4-frame change in the sync wait), so as a gate it measured timing noise. The run/heal gap it stood for is still open and still unfixed — the lane arrives at 1-5 HP — but it lives here and in the results table's `lead hp` column, not in a pass criterion of a case about arrival. If it is ever fixed, the case to write is a run/heal-policy case seeded mid-fight, not a floor bolted onto this one.
generalizes:   When a wild battle stalls (no enemy HP progress for WILD_BATTLE_PATIENCE turns), always cap the recovery run attempts and fall back to the highest-damage move; never let a single recovery heuristic consume the entire turn budget. And name an eval for the failure it detects, not for the bug that prompted it: `route1-flee-loop` kept reading as a live flee loop for a day after the loop was fixed, because the name and a criterion borrowed from a neighbouring case outlived the thing they described. A criterion a case cannot fail for its own reasons belongs in a case of its own.
